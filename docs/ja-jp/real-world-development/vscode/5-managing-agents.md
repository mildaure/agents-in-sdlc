GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しとファイルの編集をリアルタイムで確認できます。各差分をインラインでレビューし、変更を個別に採用または取り消し、追加のプロンプトで会話を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示を加え、ハイコントラストモードとともにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加したいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** コントロール付きでチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取り、編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部にある **Files changed** の表示を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出し (例: ターミナルコマンドの実行) に許可が必要な場合、エージェントは一時停止し、**Allow** の確認を表示します。内容を確認し、実行してよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更の概要が表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたら、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを使うため、エージェントは前の作業のコンテキストを保持しています。変更したコンポーネント、スタイル設定の方法、追加した Local Storage のパターンなどです。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の変更を確認して、ライトモードの追加を提案します。
3. 新しい編集が適用されるたびにレビューします。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (例: 好みと違う方法で切り替え UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 作業中のセッションに指示を追加する方が、最初からやり直すより速く済みます。追加プロンプトで調整を依頼できます (例: 「CSS を簡潔にするため、セレクターを重複させず CSS 変数を使ってください」)、方向を修正できます (例: 「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを追加してください」)、範囲を拡張できます (例: 「両方の切り替えにキーボードショートカットも追加してください」)。

## 変更内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイル全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントで指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、Local Storage による設定の保持など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、実行中のセッションを監視して指示を追加しました。ファイル編集をその都度レビューし、変更を採用または取り消し、コンテキストを維持しながら追加プロンプトで作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 実行中のセッションに追加プロンプトを送り、方向を調整する。

次の[レッスン][next-lesson]では、アクセシビリティ関連の作業をプルリクエストとして公開し、このラボでローカルカスタムエージェントが行った変更をレビューします。
